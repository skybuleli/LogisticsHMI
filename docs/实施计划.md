## 风险清单

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| OPC UA .NET 库 NativeAOT 不兼容 | 中 | 高 | 预留 JIT 部署选项，RD.xml 白名单 |
| Avalonia 12 Impeller 生产就绪→需评估 | 低 | 中 | 继续 Skia 后端，Impeller 实验性 vNext |
| 时序数据库 TDengine 在 macOS 开发不便 | 高 | 低 | Docker 运行 TDengine，起步先用 PG 存时序 |
| WMS 实际对接协议不统一 | 中 | 中 | 适配器模式 + 模拟 WMS 先行验证 |
| 工业现场网络不稳定导致频繁断连 | 高 | 中 | 断点续传 + 离线缓冲 + 指数退避重连 |
| 工控机硬件资源受限（低内存/弱 CPU） | 中 | 高 | NativeAOT 减内存、渲染帧率自动降级 |

## 执行策略建议

### 1. 垂直切片优先（Tracer Bullet）

不要按水平层逐层开发（先做完所有 Model、再做所有 View...），而是**可以快速 Demo 的路径优先**：

> **建议第一周目标：** 创建项目结构 → MVVM → DI → 日志 → 主题 → 导航 → 一个完整页面（设备列表页），连接模拟设备，显示动态数据。

这样第一周就能看到一个可运行的雏形，而非看不到结果的"地下工程"。

### 2. 并行执行策略

- Phase 1 的 1.8（窗口管理）可与其他 1.x 任务并行
- Phase 2 的 2.2~2.6 **五个驱动可完全并行开发**
- Phase 2 的 2.10（模拟设备）可与驱动开发并行
- Phase 3 的 3.3（Redis）可与 3.1/3.2 并行
- Phase 4 的 4.5（路径规划）是一个纯算法任务，可独立推进
- Phase 7 的 7.1（单元测试）从 Phase 1 开始持续贯穿

### 3. 尽早让 AI 参与的方式

每个任务启动前：
1. 读取 `AGENTS.md` 了解规范
2. 读取 `docs/实施计划.md` 确认当前任务上下文
3. 读取蓝图文档对应章节
4. 查看已完成的相邻代码（保持风格一致）
5. 完成 → 编译验证 → 记录进度

## AI 辅助执行的 SOP

每个 Agent 会话的标准化流程：

```
1. 读取 AGENTS.md → 了解项目规范和当前进度
2. 读取 docs/实施计划.md → 确认具体任务
3. 读取相邻已完成代码 → 保持风格一致性
4. 检查前置任务是否已完成（PROGRESS.md）
5. 执行任务
6. dotnet build 编译验证
7. dotnet test 运行关联测试
8. 更新 AGENTS.md 中的进度表
9. 完成会话记录
```
